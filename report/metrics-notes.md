# Metrics Notes

## Pcap Inputs

The plots are computed from switch pcaps generated by p4app:

- Transmitted traffic: `s1-eth2_out.pcap`
- Received traffic at the destination side: `s1-eth1_in.pcap`

Only TCP packets with non-empty payload are counted. Pure ACKs and other
control-only TCP packets are ignored for delivery/leakage metrics.

## Traffic Classification

Packets are classified by source IP:

- IPv4 legitimate source: `10.0.2.101`
- IPv6 legitimate source: `2001:db8:2::101`
- Any other TCP payload source is treated as attack/spoofed traffic.

## Legitimate Delivery Rate

Measures how much legitimate payload traffic reaches the destination:

```text
LDR = legitimate_received / legitimate_transmitted
```

Higher is better. This metric captures collateral damage or false positives.

## Attack Leakage Rate

Measures how much spoofed/attack payload traffic reaches the destination:

```text
ALR = attack_received / attack_transmitted
```

Lower is better. This metric captures false negatives: attack packets that the
data-plane logic allowed through.

## Validation Plot

The validation plot compares:

- Legitimate-only delivery rate.
- Spoof-only attack leakage rate.

This is meant to show that legitimate traffic is forwarded and spoofed traffic
is filtered in the simplest scenarios.

## Mixed-Traffic Plots

Mixed-traffic plots compare P4Drop, P4DropExt over IPv4, and P4DropExt over
IPv6 as the attack-flow ratio changes.

The main mixed metrics are:

- Legitimate delivery rate under attack.
- Attack leakage rate under attack.

The `mixed_0.0` run is the no-attack mixed-flow baseline. If present, it can be
used to compare degradation:

```text
normalized_LDR = LDR_with_attack / LDR_without_attack
```

This normalized value is useful for showing how much legitimate delivery changes
relative to the no-attack case.
